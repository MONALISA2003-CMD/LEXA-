URA's official information identifies system-to-system integration as an API connection and says taxpayers must register/obtain the appropriate setup; FDN, verification code and QR values are returned as fiscal-document evidence, not generated by LEXA. The URA EFRIS page describes the system-to-system route and the URA handbook directs integration support to URA. See https://ura.go.ug/en/efris/ , https://ura.go.ug/en/efris-handbook/ and https://ura.go.ug/en/efris-brochure-23-24/ .

For mobile money, MTN Uganda's official Open API page directs developers to the developer portal and describes Collections, RequestToPay and transaction-status APIs: https://www.mtn.co.ug/helppersonal/mtn-open-api/ and https://momo.mtn.com/api/ . Current MoMo developer community notes a Uganda platform/base URL migration to `https://momoapi.momo.africa` and mandatory country targeting headers; verify the registered partner account's current country-specific instructions before production use: https://momodevelopercommunity.mtn.com/product-updates .

**Not implemented or claimed in this ZIP:** real URA sandbox handshake/approval, MTN merchant credential provisioning, webhook authentication, provider status reconciliation against a merchant test account, or production payment/fiscalisation. These need registered tenant/provider credentials, approved URA/MTN test access and real acceptance evidence. No secrets belong in source or ZIP.
